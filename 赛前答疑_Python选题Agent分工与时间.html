Q1Python / MATLAB：只用 Python 行不行？

结论先行：只用 Python 完全够用，赛前 24 小时不要去装 MATLAB。

QMATLAB 有必要下载吗？它的意义在哪里？

✅ 只用 Python —— 推荐

  • 规则允许：国赛不限制软件，评审只看论文与结果
  • 生态覆盖 95% 需求：numpy/scipy（优化、积分、ODE、插值）、pandas（数据处理）、statsmodels（统计与时序）、sklearn（机器学习）、networkx（图论）、pulp/cvxpy（规划）
  • 零安装成本：你的 Anaconda 已带齐核心栈（已验证：numpy 2.3.5 / pandas 2.3.3 / sklearn 1.7.2 / statsmodels 0.14.5 / matplotlib 3.10.6）
  • AI 友好：所有 Agent / Skill（MathModelAgent、math-modeling-skill 等）对 Python 的支持都远好于 MATLAB
  • 出图更强：matplotlib + seaborn 的出版级控制力优于 MATLAB

⚠️ MATLAB 的真实意义

  • 历史惯性：早期数模教材、往年优秀论文代码多为 MATLAB，抄起来方便
  • 工具箱开箱即用：Optimization / Global Optimization / Symbolic Toolbox 不需配环境
  • Simulink：动态系统仿真，Python 无等价物（但国赛极少需要）
  • 学校要求：部分学校数模课以 MATLAB 授课，或机房只装了 MATLAB
  • 北太天元：国产 MATLAB 替代，北太振寰是 2026 国赛赞助单位，部分赛区在推广
为什么现在不要装 MATLAB：安装包 20–40 GB，安装 + 激活通常要 1–3 小时，还可能卡在 license / 工具箱缺件上。距离开赛不到 24 小时，这个时间成本换来的收益是负的。把时间花在熟悉 Python 工具包上，回报高得多。

什么时候才真的该用 MATLAB？

情况建议
队里有人 MATLAB 极熟、Python 生疏就用 MATLAB。赛前换语言是自杀，熟悉度 > 语言优劣
题目需要 Simulink 仿真国赛历史上极少，遇到再说
学校/赛区要求交 MATLAB 代码先用 Python 跑出结果，最后让 AI 转写成 MATLAB 语法即可（结果对就行）
只是"听说数模都用 MATLAB"不装。这是 2010 年代的认知
我的建议：主语言 Python（你已具备完整环境）+ 心里有数"必要时可让 AI 把代码转写成 MATLAB/北太天元格式"。
Python 真正的坑不是语言，是环境——依赖冲突、中文字体变方块、路径问题。这些我已经在 mmcore/style.py 里处理掉了（已验证：Microsoft YaHei 自动识别，出图无方块）。

Q2三人独立读题后，到底怎么定题？

核心原则：不是"我觉得这题有意思"，而是"我能把每一问的解法列全"。列不全 = 不选。

标准化的"思路卡"

每人独立读题（含附件）60–90 分钟，不许讨论，各自填一张卡：

字段要求
① 子问题清单把题目拆成 N 个小问，编号列出。列不出 = 没读懂
② 每问的解法点名具体算法（如"Q1 用 ARIMA + 灰色预测对比，Q2 用熵权 TOPSIS"）。写不出算法名 = 没思路
③ 数据可行性附件够不够？要不要外部数据？去哪找？
④ 卡点预判哪一问最可能卡住？卡住的降级方案是什么？
⑤ 信心分1–10 分，必须写理由，不许凭感觉打分

汇总投票：三个判据 + 三条规则

判据 ① 可行性

子问题清单能否列全？数据是否可得？权重 40%

判据 ② 把握度

三人信心分的最低分（不是平均分）——短板决定风险。权重 35%

判据 ③ 出彩空间

是否有建模创新点、能否做出差异化。权重 25%

三条决策规则：
① 取最低分而非平均分——一人 9 分一人 3 分的题，风险远大于两人都是 6 分的题；
② 30 分钟定不下来就选"下限稳"的那题；
③ 选题总时长设死线：18:00 发题，22:00 必须定题，超时就是全员失败的开始。

实例演练：2024 年国赛的真实三题

📋 场景：某三人队，甲（数学强）、乙（编程强）、丙（写作强）

题目：A 题「板凳龙」（几何+运动学+碰撞检测）｜ B 题「碳化硅外延层厚度」（光学干涉+优化）｜ C 题「农作物种植策略」（数据+优化+风险）

甲 · 数学强 · A 题
7 / 10
思路：螺线参数化 → 等弦长递推 → 隐式微分求速度。
卡点：问题 2 碰撞检测（板体是矩形不是点）几何复杂；问题 4 调头曲线构造没把握。
乙 · 编程强 · C 题
8 / 10
思路：Q1 相关性+聚类，Q2 熵权 TOPSIS 评价，Q3 随机森林预测，Q4 整数规划 + 蒙特卡洛风险。
卡点：最后一问多目标优化建模难，但有降级方案（单目标 + 情景分析）。
丙 · 写作强 · C 题
6 / 10
A 题只能列全 3 问，信心 4；C 题能列全 4 问且有往年论文可参照，信心 6。
决策过程：A 题只有甲 1 人 7 分，乙、丙均 <5 → 淘汰（短板决定风险）。
C 题乙 8 + 丙 6，两人都能列全子问题，且有明确降级预案 → 选 C 题。
反向情形：如果队里有物理/力学背景的人，A 题甲 8 乙 7，且能说出"用分离轴定理做矩形碰撞"——那 A 题反而更优，因为出彩空间更大（做出来的人少）。
一个反直觉的提醒：不要因为是"数据题容易"就无脑选 C。C 题做的人最多、区分度在深度——人人都能跑出图，想拿国奖必须在特征工程、模型对比、稳健性分析上超出平均。而 A/B 题做的人少，只要完整做完就是稀缺。选题要考虑你们队的比较优势，不是题目的绝对难度。

Q3Agent 时代，分工可以改成"一人统领多 Agent"吗？

先说一个硬性前提：国赛规则要求 3 人一队，所以"一人"在规则上不成立。真正的问题是：3 人的角色该怎么重定义。

Q一个人统领几个 Agent，和传统三人分工，本质区别是什么？
维度传统三人分工一人 + 多 Agent
并行方式人脑并行：三人同时独立思考，视角不同执行并行：Agent 并发跑代码/出图/检索，但视角只有一个
容错机制一人卡住，另外两人可接手或纠偏主导者判断错了，Agent 会顺着你错到底（这是最大风险）
瓶颈沟通成本、写作速度主导者的注意力 + 判断力
体力可轮休，三人接力一人 74h 全程盯，注意力崩溃比三人快得多
风险集中度分散API 限流 / 工具崩溃 / 账号异常 → 全队归零
产出上限受限于人的编码与计算速度极高——见下方 209 页案例，人类 74h 做不到的计算量 AI 能做到
最关键的认知：Agent 压缩的是"执行时间"，压缩不了"判断时间"。
那份 209 页的 GPT 论文里有一条真实记录：问题 3 的原答案 0.42021689805 m 被自检发现"在途中穿透"，修正为 0.45033741302719266 m。这种错误——数值看着极精确、推导看着极完整、但物理上不成立——是 AI 最危险的失败模式，也只有懂建模的人能发现。
如果是一个人带 Agent，你既当选手又当裁判，这种错误极易漏网。

推荐模式：3 人保留，角色重定义为「出题人 / 审核人 / 整合人」

🎯 总指挥
1 人。负责选题拍板、子问题拆解、模型选型、对 AI 输出做最终判断。这是全队最累也最关键的岗位，必须由建模能力最强的人担任。
配：建模 Agent（思路建议 + 模型选择）
🔬 审校官
1 人。不写代码，专门挑错：验算关键数值、检查模型假设是否自洽、用模拟评委视角打分。传统分工里没有这个角色，Agent 时代必须有。
配：评审 Agent（BZDmathclub 的评阅细则蒸馏 Skill）
🧩 整合官
1 人。把 Agent 产出的代码、图、文字碎片收敛成一条逻辑主线，负责论文叙事与排版。Agent 最容易产出"局部正确、整体失联"的内容。
配：写作 Agent + 出图 Agent（sci-box）

Agent 编队建议（4–6 个足够，不是越多越好）

Agent职责
建模 Agent读题拆解、子问题清单、模型决策树
编程 Agent写代码、跑数、调参（Codex / Claude Code）
出图 Agent出版级图表 + 技术路线图（sci-box）
写作 Agent基于真实结果生成论文段落
评审 Agent模拟评委挑错、打分（封稿前必跑）
查证 Agent文献检索、公式核对、数值一致性检查
Agent 越多越好的误区：超过 6 个后，你的时间会全部消耗在"管理 Agent"而不是"做建模"。4 个 Agent + 3 个人是甜点区。
三条铁律：
① Agent 不能投票定题——选题必须人定，AI 对"哪题更适合你们"没有信息；
② Agent 写的结论必须人工验算一遍关键数字；
③ 保留一个不用 AI 的独立验算——哪怕只是用 Excel 手算一个小样本，用来交叉验证 AI 的量级。

Q4跑数据到底需要多久？

给你一个可量化的预期。注意：跑数据不是最耗时的，论文才是。

通用时间预期（C 题 · 人类队 · 无 AI）

环节耗时说明
数据清洗 + EDA4–8 h盘点、缺失、异常、编码、描述统计、6–8 张探索图
第 1 问建模求解6–10 h第一次跑通端到端最慢，要定框架
后续每问4–8 h/问含"加一个对比模型"的时间
灵敏度 / 稳健性3–5 h别省，这是 C 题拉分项
正式出图5–9 h10–15 张出版级图，含改配色、改标注的反复
论文写作 + 排版28–38 h这才是大头，占总时长 40–50%
合计60–75 h刚好卡满 74 小时 —— 这就是为什么"完整比完美重要"
时间占比规律（很重要）：跑数据 + 出图 ≈ 30–40%，论文 ≈ 45–50%，其余是选题、讨论、休息。
新手最常见的翻车方式：在跑数据上耗掉 60 小时，最后 10 小时赶论文 → 论文残缺 → 直接失去评奖资格。

Agent 辅助后能省多少？

代码编写

-60~70%

AI 写初稿 + 人调试。省得最多，也最安全

出图

-40~50%

省在样式代码，省不了"选什么图"的决策

建模思路

-10~20%

几乎省不掉。这是人的活，也是评分核心

净效果：整体压缩 30–40%，即从 70h 降到 42–50h。
省下来的 20–28 小时不要用来"多做两问"，要用来"把已做的做扎实"——加对比模型、做灵敏度分析、精修图表、打磨摘要。这些才是真正拉开档次的动作。

Q6结论与行动清单

✅ 四个问题的直接回答

  1. 只用 Python 完全可以，MATLAB 现在不用装。它的意义主要是历史惯性与教学传统，以及北太天元的国产替代场景
  2. 定题靠"思路卡 + 取最低分"：能列全子问题 + 点名算法才算有思路，取三人中的最低分而非平均分，22:00 前必须定题
  3. 3 人保留（规则要求），角色改为总指挥 / 审校官 / 整合官，配 4–6 个 Agent。一人统领的风险是"没人能纠正你的判断错误"
  4. 跑数据 + 出图 ≈ 30–40%，论文 45–50%。Agent 省 30–40%，省下的时间用来做扎实而非做更多

🎯 今晚的行动（按优先级）

  1. 确认环境：python -c "from mmcore import env_check; env_check()"
  2. 跑通示例：python example_pipeline.py，确认出图中文正常
  3. 三人拉群，约好明晚 18:00 各自独立读题、22:00 汇总投票，并把"思路卡"模板发群里
  4. 确定谁当总指挥 / 审校官 / 整合官，现在就定，不要现场分
  5. 装好要用的 Agent / Skill（若使用），并测一次 API 连通性
  6. 阅读当届《人工智能工具使用规定（2026 年试行）》，确认是否需声明 AI 使用情况
