## 本文件负责

本文件是 P9 隔离复现、P10 多角色对抗审查、finding 关闭、失败回退、独立盲审、质量标签、适用答辩和最终验收报告的唯一规范。

## 本文件不负责

本文件不修改模型结果来迎合评审，不自行宣布获奖，也不以审稿人数量替代审查质量。
审查发现必须回到来源实体修复；不能只润色答复或降低报告严重度。

## P9 隔离复现

隔离复现从新的空 attempt 目录开始，只使用冻结的 source artifacts。
不得复用原 execution 的输出目录、缓存、临时文件、内存对象或未登记环境状态。

复现前冻结：

- 数据、代码、配置和依赖 artifact ID；
- 命令参数和环境白名单；
- 随机种子策略；
- 预期输出；
- 每个输出的 `sha256`、`json_exact`、`json_numeric` 或 `statistical_json` 比较策略（与 `references/evidence-and-claims.md`、`references/isolation-runtime.md` 三处枚举一致；多种子/随机协议使用 `statistical_json`）；
- 数值容差、随机统计标准和失败条件；
- 资源限制与超时。

复现过程中保存原始 stdout/stderr、退出状态、文件变化和输出哈希。
启动失败、超时、非零退出、额外输出、缺失输出或沙箱外写入均为失败。

结果比较逐输出报告，不只给一个总状态。
容差不得在看到失败后扩大；若原策略不合理，回退 P4 修订并将既有确认性主张降级。

复现失败先定位：环境、输入、随机性、实现、数值非确定性、隐藏依赖或原结果篡改。
不得删除失败 attempt 后重新运行直到通过。

P9 通过只证明当前冻结源在声明环境下可重建核心输出，不证明模型科学上正确。

## 稿件附录代码闭包核验

P9 从冻结源复现；稿件附录闭包核验则从一个独立角度防止"论文附录展示的代码与论文数值脱节"：

1. 从最终稿件（LaTeX 源或最终 PDF）的附录区域提取全部代码块，仅提取标注为对应语言（如 Python）的块，跳过依赖清单、README、配置示例等非代码块；提取必须可审计，记录块来源位置。
2. 将提取代码写入全新目录，不使用原工作的缓存或输出；在注册过的环境中空目录重跑，随机种子与输入闭包登记与 P9 一致。
3. 将重跑输出的科学数值（含置信区间、单位）与稿件正文、摘要逐项核对，数值一致且脚本可运行才算通过；任何数值差异或运行失败都视为失败。
4. 失败时先定位根因：提取遗漏、代码版本不一致、环境差异或论文数值手改；修复上游（论文或源代码）后重新提取与重跑，不扩大容差。
5. 若赛项允许把部分代码移入支撑材料而附录只放核心脚本，核验范围对应改为支撑材料中的全部代码，并在报告注明代码来源。

该核验在 P8 之后、P10 论文合规审查之前进行；结果作为论文合规审查的辅助证据，不能替代 P9 的冻结源复现报告。

## 附录中非 Python 工具呈现

若分析过程使用了非 Python 工具（Excel 公式、SPSS/Minitab/Stata 语法、MATLAB/Mathematica 脚本、LINGO/Gurobi 等求解器命令），附录不能只写"使用 XX 求解"，必须给出可独立复现的完整操作信息：

- **Excel**：关键单元格公式、求解设置（目标单元格、变量、约束、求解器选项）与输出位置；
- **SPSS/Minitab/Stata 等统计软件**：完整语法或逐级菜单操作路径与关键选项；
- **MATLAB/Mathematica/R 脚本**：入口脚本、参数与输出文件对应表，数值与论文一致；
- **LINGO/Gurobi/CPLEX 等求解器**：数学模型与语法代码、参数设置、退出条件；
- **工具间数据流**：输入输出文件路径、执行顺序与依赖关系。

核验标准：按附录给出的操作信息能独立重建所声称的结果；重建不出时改为可复现实现，或在附录中如实说明不可复现原因。该要求补充但不替代稿件附录代码闭包核验，只覆盖非 Python 部分。

## P10 五角色审查

至少按五个相互独立的问题视角审查：

### 赛题评委

- 每项显性和隐含要求是否有直接回答；
- 方案是否解决决策问题而非展示技术；
- 关键洞察、比较和限制是否清楚；
- 小问依赖与统一框架是否自然；
- 摘要能否准确概括证据。

### 数学与数值

- 定义、单位、推导和定理条件是否正确；
- 边界、退化、特例和反例是否处理；
- 优化可行性、界与 gap 是否匹配措辞；
- ODE/PDE 离散、稳定和收敛是否充分；
- 数值容差和病态性是否可能改变结论。

### 数据与统计

- 分析单位、划分和依赖结构是否正确；
- 是否有时间、空间、主体或预处理泄漏；
- 指标、区间、效应量和多重比较是否合理；
- 因果识别和外推是否越界；
- 选择性报告和不利结果是否被隐藏。

### 复现

- source artifact 覆盖是否完整；
- 空目录能否重跑；
- 输出比较策略是否预登记且未放宽；
- demo、fixture、跨运行和陈旧产物是否隔离；
- 论文绑定能否追到 execution 和结构化位置。

### 论文与合规

- 论证、图表、表格、引用和限制是否清楚；
- 当届格式、匿名、文件名和支撑材料是否合规；
- PDF 实际渲染是否可读；
- 裸数字、占位、元数据和内部路径是否清零；
- 交付包是否与 manifest 一致。

五角色可以由一个宿主分次执行，但不得把同一次自我评价伪称独立代理。

### 实体锚定质询与红队反证

为防止审查退化为无锚点的泛化评价，五个角色的每个检查项必须落到具体 Registry 实体或稿件位置：

1. **质询输入派生**：每轮审查开始前，从 Registry 导出三份清单作为提问素材——问题契约的逐条要求、全部 VALID claim 及其支持证据、figure 与 result 的绑定表。质询从清单出发（例如"claim C-07 声明的适用边界在稿件哪一节被重述？"），不从整体印象出发。
2. **实体锚定 finding**：每条 finding 必须引用至少一个实体 ID（requirement 编号、claim_id、result_id、figure_id）或精确稿件位置；无法锚定的观察只能记为备注，不进入审查结论。锚点使修复动作和关闭验证可以被程序化对照。
3. **红队反证轮**：常规五轮之外增加一轮专门攻击——对摘要与结论中的每个核心 claim 构造"它可能错误"的具体场景（数据子集、参数区间、替代解释、退化条件），逐一核对既有验证是否覆盖该场景；覆盖缺失且影响主结论的，升级为 MAJOR finding 进入正常关闭流程。

### 评委视角终读模拟

P10 审查完成后，增加一次"疲劳评委快速翻阅"视角的终读模拟：模拟评委在有限时间和注意力下翻阅论文，检查核心信息是否能在快速浏览中被准确获取。

终读检查项：

- 摘要是否在快速浏览中传达问题、方法、核心结果和限制；
- 每章开头是否有明确的方向性句子，使评委无需细读即可定位内容；
- 关键图表是否有自解释的图注，不依赖正文才能理解；
- 主结果表是否在独立阅读时清晰可辨，数值和单位完整；
- 贡献声明是否能被快速定位，且每个贡献有证据指向；
- 是否存在"翻三页才看到实质内容"的冗长前奏。

终读模拟不替代结构化审查；它检查的是论文的可读性和信息密度，确保评委在有限时间下能准确理解核心贡献。终读发现的问题登记为 MODERATE 或 MINOR finding，在提交前修复。

## Finding 生命周期

每个 finding 记录：

- `finding_id`；
- 审查角色与严重度；
- 具体证据和文件/实体位置；
- 受影响的 claim、result、figure、formula 或 rule；
- 根因假设与确认依据；
- 最早 `rollback_stage`；
- `rerun_scope`；
- 状态；
- 修复 execution 或新实体；
- `closure_evidence`；
- 关闭后需重跑的门禁。

严重度语义：

| 严重度 | 含义 | 发布处理 |
|---|---|---|
| `CRITICAL` | 编造、完整性破坏、核心错误、重大违规或结论相反 | 必须修复并关闭 |
| `MAJOR` | 核心主张证据不足、复现失败、泄漏、约束或规则风险 | 必须修复并关闭 |
| `MODERATE` | 影响范围、稳健性或解释但不推翻核心 | 修复或降低主张后关闭 |
| `MINOR` | 不影响核心结论的表达、局部可读性或维护问题 | 记录，可排期 |

关闭 finding 必须引用新证据，且检查受影响实体的血缘和门禁。
把 `severity` 改小、删除 finding 文件或写“已解决”不构成关闭。

若通过降低主张关闭，Claim 创建新版本，摘要和结论同步更新，并重新绑定。

关闭模式（与 `close-finding --mode` 对应）只有两种：

- `CLOSED`：已按修复路径消除问题；关闭证据必须是更晚创建、当前 VALID 的修复实体或通过门禁报告。
- `ACCEPTED_LIMITATION`：确认缺陷真实存在但属于可披露限制（如数据边界、外部依赖不可得），以降级后的 Claim 限制字段或披露文本作为关闭证据；该模式仅对 `MODERATE`/`MINOR` 合法，`CRITICAL`/`MAJOR` 不得以此关闭，且发布标签仍会如实反映"存在接受限制"，不视为无保留通过。

## 回退与最小重跑

恢复遵循：定位最上游根因 → 新尝试 → 失效传播 → 最小子图重跑 → 重新门禁。

典型回退：

- 赛题解释或需求漏项：P2；
- 数据源、单位、泄漏或文献错误：P3；
- 指标、划分、模型选择或容差计划错误：P4；
- 代码、求解器或结构化输出错误：P5；
- 验证不足或主张越界：P6/P7；
- 论文绑定、图或叙事错误：P8；
- 环境和隐藏依赖：P5 或 P9，按根因判断；
- 当届规则变化：P0，并使相关合规产物陈旧。

回退使目标阶段活动，下游阶段变为 `INVALIDATED`，受影响实体传播 `STALE`。
未受影响的独立子图可保留，但必须由 Lineage 证明，而非人工宣称。

每次修复创建新的 attempt，不覆盖旧运行。
三次针对同一症状的修复仍失败时，重新审查架构和问题形式化，不继续堆补丁。

## 独立盲审

有独立代理能力且用户授权时，盲审只提供：

- 新 skill 或作品本身；
- 原始赛题和必要附件；
- 公开规则或指定审查任务；
- 运行所需最小环境说明。

不得提供作者的缺陷清单、期望答案、修复意图、先前结论或暗示性评分词。
审查者应从原始材料独立识别问题。

不同前向任务使用全新隔离目录，避免前次产物泄露。
原始输出、日志和 finding 作为实验支持保存。

若独立代理不可用，执行同一 AI 的隔离角色审查，并明确披露独立性限制。
不能把角色切换称为真正独立审查。

## 质量发布标签

标签只描述当前证据状态：

- `NOT_READY`：任一红线、门禁失败、重大 finding 或合规未知；
- `REPRODUCIBLE`：完整性、血缘、隔离复现和基本合规通过，但质量证据尚未齐全；
- `QUALITY_REVIEW_READY`：质量证据齐全，等待专业审查；
- `SPECIAL_PRIZE_CANDIDATE`：前项基础上，题目响应、正确性、实质贡献、论文质量和真正独立盲审均通过；
- `SPECIAL_PRIZE_CANDIDATE_LIMITED_REVIEW`：除独立代理不可用外满足候选要求，并披露限制。

这些标签不能保证奖项。
评委偏好、竞争作品、领域原创性、公开数据真实性和审美仍具有外部不确定性。

若没有真正独立审查，最高只能使用 `SPECIAL_PRIZE_CANDIDATE_LIMITED_REVIEW`。
任何程序不得仅因总分达到阈值自动写入候选标签；质量评估要逐维引用证据并确认红线清零。

## 答辩准备

先核验赛事是否需要答辩。
不需要时登记规则化不适用，不为“显得完整”强行制作材料。

需要时，答辩材料复用最终 Registry 当前版本的数字、图和主张。
不得从旧幻灯片或手工表复制。

演示结构围绕：

- 问题和决策价值；
- 数据与关键假设；
- 模型结构和为何选择；
- 核心结果与基线；
- 正确性、稳健性和反证；
- 可执行建议；
- 限制和复现。

预问不按固定题数凑量，覆盖最可能推翻结论的问题：

- 为什么不用更简单或不同模型；
- 关键假设被违反会怎样；
- 如何排除泄漏和过拟合；
- 最优性、显著性或因果措辞凭什么；
- 结果对参数、数据和情景有多敏感；
- 哪些限制会改变建议；
- 代码能否复现；
- 与题目每问如何对应。

答案必须引用证据或诚实承认边界，不使用无法证明的防御性表述。

## 最终验收报告

最终报告严格区分：

1. 程序证明：策略、账本、Registry、哈希、绑定、复现和包校验；
2. 实验支持：适配验证、恶意回归、前向行为和可移植性；
3. 专业判断：模型价值、洞察、创新、写作和候选质量；
4. 无法保证：数据真实性、领域原创性、评委判断、竞争结果和最终奖项。

报告列出：设计与计划哈希、测试数量、validator 状态、所有 SKIP、独立审查状态、开放 finding、发布标签和剩余限制。
不得把“测试全绿”写成“模型必然正确”或“必然获奖”。

## 阶段验收

P9 必须有隔离空目录、新 execution、冻结比较策略和逐输出复现报告。
P10 必须证明：

- 五角色均完成结构化审查；
- 所有 CRITICAL 和 MAJOR finding 已用真实证据关闭；
- MODERATE 已修复或主张降级；
- 修复经过失效传播、最小重跑和重新门禁；
- 独立盲审状态真实披露；
- 质量标签没有越过审查独立性上限；
- 答辩数字和图只来自最终 Registry，或规则化不适用；
- 最终报告四类结论没有混写。

审查角色名称、finding 文件数量或自评分数不能自证通过。


## 附录：v2 审查与发布

### 五角色 review_report

- 五个角色（competition_judge、mathematics_numerics、data_statistics、reproducibility、paper_compliance）各必须有一个独立 `review_report` 证据：`role`、`scope`、`checks`、`finding_ids`、`reviewer_mode`（same_agent_roleplay / independent_agent / external_reviewer）。
- 同一报告不得充当多个角色；报告必须晚于 P8 门禁；finding ID 必须与角色记录一致。
- 任一角色使用 same_agent_roleplay 时 `independent_review` 必须为 limited，最高发布标签为 `SPECIAL_PRIZE_CANDIDATE_LIMITED_REVIEW`。

### 质量 rubric

- 八个维度按 `quality_rubric` 只接受允许的证据类型；同一证据实体只能支持一个维度；`total` 必须等于分项和且达到阈值。
- 标签由 `mmflow release-status` 程序计算：任一红线、开放 CRITICAL/MAJOR finding、完整性错误、必需测试失败 → NOT_READY；完整性通过但质量证据未齐全 → REPRODUCIBLE；质量证据齐全但审查角色缺失 → QUALITY_REVIEW_READY；审查角色完整但不独立 → SPECIAL_PRIZE_CANDIDATE_LIMITED_REVIEW；审查角色完整且独立 → SPECIAL_PRIZE_CANDIDATE；不承诺评委决定与奖项。
