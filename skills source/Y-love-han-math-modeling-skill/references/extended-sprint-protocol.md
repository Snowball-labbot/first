## 本文件负责

本文件保留第二版 Skill 的可执行节奏设计：里程碑、优先级、逐问闭环、基线先行、失败恢复、上下文断点、论文与答辩并行准备。它帮助在竞赛时间压力下减少返工，但所有事实仍必须由 mmflow 记录。

## 本文件不负责

本文件不允许跳过 P0-P11，不创建并行事实源，不用文件存在、关键词、页数或图数证明阶段通过，不定义赛事规则，也不覆盖 `scripts/mmflow.py` 的状态机、账本、门禁、回退、复现和发布标签。

## 冲刺启动

1. 运行 `doctor`、`init` 或 `resume`、`status` 和 `next`，确认唯一活动阶段。
2. 建立任务看板：当前阶段、最上游风险、必须登记的证据、下一门禁、预计耗时、计算预算和最小可恢复点。
3. 将工作分为三条互相依赖的线：证据线、计算线、表达线。表达线只能消费已登记的生产证据。
4. 每个阶段只选择一个主目标和一个备用路径。备用路径必须在 P4 登记，不能在看到结果后偷偷换规则。
5. 采用“先闭环、再加深”：先完成可验证的基线和最小答案，再投入统一框架、理论深度、稳健性和表达优化。

### 门禁必需最小登记集与载荷契约（唯一事实源）

各阶段门禁必需证据类型、逐字段登记配方、代际纪律、链式注册顺序与
程序化自省命令，已统一收敛到 `references/evidence-registration-cookbook.md`
（P0–P11 全阶段参考路由均包含它；`next` 返回的当前阶段参考清单可见）。
机器可读同源入口：

```text
python scripts/mmflow.py schema   [--evidence-type T] --json
python scripts/mmflow.py adapters --json
python scripts/mmflow.py cookbook [--stage Pn]      --json
```

冲刺期间只读该手册对应行即可完成登记自检，本文件不再重复维护第二份
配方表（避免双事实源漂移）。

### 参考编排器

`scripts/auto_drive.py` 是 P0→P11 的计划驱动参考编排器：入口为
`python scripts/auto_drive.py <project_root> <gen_tag> [step ...]`，
步骤序列缺省覆盖 p0→p1→p2→p3→p4→…→p11(prep/pack/scan/ev)→finish。
前置条件：先人工运行 `mmflow init --competition ... --edition ...`
（赛事名称与届次是用户事实，编排器不代填）。所有载荷来自项目内
`autodrive/plan.json`（按赛题替换 CONTENT 区），全部状态转换经官方
CLI 子进程执行（自动持有单写者锁）；每步先 `gate` 后 `advance`，
FAIL 即带非零退出码停止，不静默跳过。

## 每问闭环

对每个小问依次完成以下事务；顺序由状态机和阶段门禁控制，以下是专业工作清单：

1. 读取题目原文位置，写问题契约和小问依赖。
2. 列出变量、单位、约束、评价指标、可识别性假设和主张类型。
3. 建立最低合理基线，保存结构化结果和失败日志。
4. 生成少量候选模型，比较合法性、可解释性、表现、计算代价和验证需求。
5. 冻结分析计划：数据边界、划分、指标、随机种子、容差、停止规则和选择方式。
6. 用受控 production execution 实现主模型，输出结果契约、图表源数据和运行环境闭包。
7. 执行题型适配验证、边界/退化测试、敏感性或不确定性分析，并主动寻找反例。
8. 登记结果、公式、图、claim 和论文绑定；不手抄数字。
9. 运行 gate；失败时修复最上游根因或回退，不直接改门禁状态。

## 时间与上下文管理

### 里程碑

每个阶段开始时估计“必须完成项、可选增强项、最坏耗时、停止条件”。若资源不足，先保住题目响应、合法基线、核心验证、复现和交付合规，再削减不必要的视觉和扩展实验。

上游决定变化时，按状态机 `rollback` 是正常机制而非失败记录：stage_epoch 递增只表示最小重算范围被程序标记。因此应在 P4 尽早冻结关键选择；冻结后若发现更优方案或上游错误，坦然回退并重跑受影响子图——不为避免回退而放弃改进、隐瞒上游修改或绕过失效传播。

### 上下文断点

长阶段或会话切换前运行 `checkpoint`，载荷至少包含当前阶段、已通过门禁、待登记实体、最上游风险、下一条命令、重跑范围、未完成事务和安全边界。恢复时先运行 `resume`、`status`、`next`，不要凭记忆继续写稿。

#### 上下文压力分级

剩余上下文比例可作为何时主动 checkpoint 的操作启发式（估算值，不是程序事实）：

- 充足（约大于 40%）：正常节奏推进当前阶段。
- 中等（约 20%-40%）：精简冗余输出，避免整文件粘贴和大段重复读取，提前准备 checkpoint 载荷。
- 高压（约 10%-20%）：立即运行 `checkpoint` 并完成结构化载荷，结束当前原子操作后不再开启新事务。
- 危险（低于约 10%）：只保存状态并停止专业工作。

该分级只决定何时主动断点；恢复一律以 `resume`、`status` 和 `next` 返回的程序状态为准，不凭比例估算凭记忆续写。

#### 断点载荷结构化格式

为提升跨会话恢复的准确性和减少信息丢失，checkpoint 载荷可使用以下 7 段结构化格式。格式是恢复辅助，不替代 mmflow 的 `checkpoint` 命令和状态机；实际恢复仍由 `resume` 读取程序状态驱动。

1. **阶段状态**：当前阶段 ID、stage_epoch、已通过门禁列表、当前门禁状态。
2. **实体快照**：已登记的 VALID 实体 ID 列表（artifact、result、claim、formula、figure、citation），待登记实体清单。
3. **任务上下文**：当前小问 ID、问题契约摘要、正在执行的候选模型、冻结分析计划的关键参数。
4. **风险与限制**：最上游风险、已知限制、未关闭的 finding ID 列表、安全边界。
5. **恢复指令**：下一条建议命令、重跑范围、依赖的前置实体 ID。
6. **未完成事务**：尚未完成的验证项、待写入的论文段落、待生成的图表。
7. **时间信息**：当前阶段开始时间、已用时间、剩余预算、最后修改时间。

每段内容必须来自 mmflow 的实际状态查询，不能凭记忆填写。恢复时按段对照实际状态，发现不一致时以程序状态为准。

### 并行边界

可并行准备规则摘要、引用核验、图表设计草案和答辩问题，但不可并行写入状态、Registry、门禁报告或同一生产输出。论文草稿、展示模板和质量代理只能读取已冻结或已登记的内容。

### 版本、依赖和紧急预案

- 每个里程碑保存代码、配置、输入、结果和稿件哈希；如使用 Git，提交记录是辅助证据，不能替代 mmflow 账本和 Registry。
- 依赖文件只描述可安装内容；真正的复现证据还必须包含解释器版本、包版本、系统能力、import 清单、随机协议和允许的环境漂移。
- 时间不足时按“规则与题目响应 → 无泄漏数据和基线 → 主模型和适配验证 → 复现与合规交付 → 论文表达增强”的顺序保底；绝不通过跳阶段、删除失败或伪造结果换取进度。
- 计算超时先缩小合法问题规模、采用可解释降阶、复用已登记的冻结输入或改变算法实现；改变指标、数据边界或选择规则必须回到 P4 登记。
- Python 环境损坏（安装失败或核心包导入报错）：先用完整解释器路径和新建虚拟环境重试；仍失败时改用 numpy/scipy 与标准库的等价实现，跳过依赖损坏包的功能，并在论文限制中披露替代方案与影响。
- 磁盘空间不足：降低图表输出分辨率、清理临时缓存和未登记的中间副本后重试；优先保证 PDF、交付清单与复现入口完整，再补齐高分辨率产物，不删除已登记的失败尝试。
- LaTeX 编译反复失败：先修复编译日志中的最上游错误；多轮修复无效时，**先核对当届官方提交格式**——当届强制提交 PDF 时不得启用 docx 兜底（那会直接制造合规 NOT_READY），应改用更保守的文档类/最小工作集二分定位编译根因；仅当当届接受 docx 或格式未强制时，才用 pandoc 或 publication 层 Word 导出模板产出 docx 保底交付物并在交付报告披露降级原因。无论哪种路径都不以缺少交付物换取进度，也不伪造渲染结果。
- 训练显存不足（CUDA OOM）：先减小批量并配合梯度累积，再尝试混合精度或缩小模型规模；降级后的训练配置、耗时与指标影响登记进执行记录，论文限制中如实说明，不把降级配置伪装成原配置的结果。
- 工具不可用时登记能力限制并选择等价替代；若仍无法形成可信答案，创建结构化 BLOCKED 报告，附已完成安全产物和恢复命令。

## 失败恢复

- 代码错误：先保留原 execution，再修复并创建新 attempt。
- 结果变差：检查基线、划分、指标方向、实现和数据边界，不因结果不理想而改指标。
- 不收敛：区分数值问题、不可行问题、识别问题和模型不匹配，登记诊断后选择降阶或替代模型。
- 证据冲突：保留两套结果，核对来源、版本、单位、随机性和适用条件；不能用平均或删除解决矛盾。
- 论文不一致：从绑定关系找到根因，重新生成受影响图表或稿件并重跑门禁。
- 复现失败：按最早不一致输出回溯，失效其后代，重新运行最小受影响子图。
- 审查 finding：修复实体并生成关闭证据，不能只把 finding 改成关闭。

## 交付前冲刺清单

1. P9 在新空目录复现核心结果，记录允许的环境差异。
2. P10 完成数学、数据、复现、论文和合规角色的结构化审查；重大 finding 必须关闭。
3. P11 运行隐私、匿名、路径、许可、压缩包解压和 smoke 检查；只打包显式允许文件。
4. 生成论文、代码、配置、数据说明、复现说明、支撑材料和适用的答辩材料，并逐项登记。
5. 运行 `audit` 和 `release-status`，读取程序计算的标签和未决限制。
6. 最终报告逐项列出全部 NOT_APPLICABLE 决策、判定依据和替代验证安排，供用户复核适用性判断；不隐藏、不合并、不省略。
7. 向用户报告通过的程序事实、实验支持、专业判断、未解决风险和无法由 Skill 保证的外部结果。
