## 本文件负责

本文件是 P8 论文证据链、摘要、符号、公式、图表、表格、LaTeX 绑定、渲染和可读性，以及 P10 论文角色审查的唯一规范。
目标是让评委能迅速理解题目回应、模型为何可信、结论能做什么和不能做什么。

## 本文件不负责

本文件不凭模板生成结果、不规定固定篇幅、图数、3D 图数、公式数或创新数，也不替代当届格式规则。
视觉精致不能补救模型错误、数据泄漏、无来源数字或不可复现。

## 从证据链组织论文

论文结构从 Requirement Matrix、Problem Contract 和 Claim Registry 生成，而不是按空模板填充。
每个核心章节回答：

1. 赛题要求什么；
2. 采用了什么可检验解释；
3. 数据和假设是什么；
4. 模型如何建立并为何适用；
5. 如何求解和验证；
6. 结果及不确定性是什么；
7. 结论的适用范围、反证和限制；
8. 如何连接下一问或最终建议。

问题重述只提炼决策对象和数学本质，不大段复制赛题。
方法章节给出足以重建的定义、推导、算法、参数和数据流，不仅罗列方法名。

每个小问结尾给明确答案，并绑定 requirement ID 和 claim ID。
讨论章节比较基线、候选、外部文献和失败场景；不重复结果表文字。

整体叙事保持统一术语、变量、单位和场景。
若不同小问使用不同模型，解释接口和依赖，不强行包装成一个不存在的统一模型。

## 摘要与贡献

摘要应在有限篇幅内包含：

- 问题和决策对象；
- 数据或证据来源；
- 核心模型结构和关键假设；
- 经绑定的主要结果及其单位、场景和不确定性；
- 与基线或现有方法的实质差异；
- 关键限制或适用范围；
- 对每问的直接回答。

摘要中的每个科学数字必须绑定 Result、Given、Citation、Formula 或 Rule 实体。
“显著提高”“全局最优”“首次”“普适”“稳健”等强词必须有相应证据和范围。

贡献不是方法清单。
只有满足以下至少一种且证据充分时写为贡献：

- 提出与题目关键困难匹配的新结构或统一机制；
- 推导非平凡性质、界或可解释关系；
- 解决识别、约束、计算或不确定性难点；
- 产生反直觉但经反证检验的决策洞察；
- 建立可复现、可迁移且优于合理基线的方案。

不按固定数量凑创新。
若主要价值是严谨验证或透明边界，可以诚实表述，不把常规算法改名为原创。

摘要不追求撑满页面。
篇幅较短只触发题目响应和证据密度诊断；不得注水、放大字体或堆图。

### 摘要结构参考

摘要的组织方式参考，不构成硬性字数指标；篇幅由题目与赛项规定决定。

**逐问段落组织**：每问一段，以"针对问题 X"开头，段内依次给出：方法全称（含具体模型结构，不写"本文模型"式无信息量指代）、关键边界或推导要点、绑定 Registry 的数值结果（含单位、场景和置信区间或不确定性范围）、与最低合理基线或文献方法的定量对比。段落顺序与赛题小问顺序一致，各段长度均衡；某段明显偏短时检查该问证据是否充分，而不是空话补足。

**摘要禁则**：

- 不引用图表编号、公式编号和参考文献编号，摘要必须自包含；
- 不出现未定义缩写或自造术语；
- 摘要中的科学数字在 P8 完成后与正文对应章节逐项核对，不允许同一概念摘要与正文数值不一致；
- 关键词与适用条件不能缺失，不能靠遗漏限制换取更强的表述。

**标题-摘要-关键词三方一致**：标题中的核心方法名须在摘要中以全称出现；每个关键词在正文中必须有实质内容支撑；三处的术语、单位与符号一致。

**人称统一**：全文在"本文"与"我们"之间选择一种，摘要不单独混用。

### MCM/ICM 英文摘要结构参考

英文摘要面向英文读者，可用以下六要素组织内容，各要素篇幅由内容决定而非平均分配：

1. **Problem Framing**：一句话给出题目决策对象、背景与要回答的问题；
2. **Approach Overview**：模型结构、关键假设与求解方法要点，不使用未解释缩写；
3. **Per-Question Results**：逐问核心结果，含单位、数值与置信区间或不确定性，并注明与基线/文献的相对差异；
4. **Cross-Validation**：至少一个验证证据（独立数据回测、交叉、校准或敏感性）并注明验证方式；
5. **Innovation & Contribution**：与基线或已有工作的结构性差异，不写无边界支撑的"首次/最优"；
6. **Conclusion & Limitation**：结论、适用条件、复现入口与已知限制。

表达注意句长交替（约 8-35 词）、动词变化，避免连串 "Furthermore"、"Moreover" 模板过渡。英文摘要同样自包含，不引用图表编号、公式编号或参考文献编号。Summary Sheet 篇幅与页数以当届官方格式为准，本结构只负责内容组织。

### 摘要首句冲击力参考

摘要首句承担在阅读第一秒建立印象的功能，可从以下三种姿态中按题目气质选择，不是强制模板：

1. **矛盾型**：指出直觉、常识或常规做法与本题实际证据相冲突之处，如"直观上 X 更优，但数据与回测显示 Y"；
2. **反直觉型**：用一句经数据或推导初步支持的反直觉观察开场，先设悬念后回答；
3. **空白型**：点出已有方法在本题关键环节的空白，顺势引出本文位置。

首句建议控制在约 50 字以内并包含具体对象或数值，避免"随着…的发展""本文提出…"式开场。首句承诺的内容必须在摘要其余部分与正文中被证据兑现，不写无法兑现的夸张表述。

### 论文标题设计参考

标题是评委的第一筛选器，按信息密度从高到低组织：

1. **方法名具体化**：出现核心模型或算法的全称、公认缩写或机制性描述，避免"基于智能算法的""新型"式空泛修饰；
2. **对象与场景锚定**：点明研究对象、关键机制或数据特征，使读者不看摘要也能判断题目领域与切入角度；
3. **结论克制**：仅在证据充分时使用效果性短语；优先描述结构与视角而非宣称优劣。

标题定稿前检查三问：每个词是否都携带信息？方法名能否在摘要首段被找到（标题—摘要一致）？关键词能否自然从标题和摘要导出？标题改动后同步复核摘要、关键词与正文术语一致性。

## 符号假设公式与衔接

符号表按对象分类，记录定义、单位、索引域、是否观测、是否决策、是否随机和首次出现位置。
同一符号全篇含义唯一；不同量不能因字母方便而复用。

假设逐条说明：

- 假设内容；
- 为什么需要；
- 题面、数据、文献或机制证据；
- 违反时影响哪些公式和主张；
- P6 如何放松或检验；
- 最终是否仍保留。

论文成稿时每条假设可压缩为一句三要素模板：「假设 X：……。必要性——去掉后……将不可解或明显失真；合理性——题面第…处/数据特征……/文献……；违反后果——……，已由 P6 的……检验量化（图/表编号）。」

公式必须：

- 变量先定义；
- 量纲一致；
- 约束和定义域明确；
- 索引、求和范围和边界完整；
- 外部定理条件核验；
- 经验常数来源绑定；
- 与代码实现和结构化结果对应；
- 在极限、边界或特例下合理。

只展示最终公式而省略决定性推导会削弱可信度。
但不必把机械代数全部展开；保留关键变换、近似、误差和选择理由。

小问衔接引用实体和数据流。
例如"Q2 使用 Q1 的参数估计"必须引用参数 Result 和不确定性，而不是只写"根据上文结果"。

### 公式合法性结构化检查参考

对每个编号公式可使用以下 5 项检查清单辅助验证数学合法性。检查结果登记为 `formula_validity_record` 证据。不要求每个公式都必须通过全部 5 项——某些检查对纯数学问题不适用，适用性不足时登记原因。

1. **量纲一致性**：等式两边量纲是否一致？对物理或工程类问题强制执行；纯数学问题可登记不适用。
2. **边界行为合理性**：参数取边界值（0、∞、负数、极大值）时公式行为是否符合物理或数学直觉？
3. **特例退化检验**：公式退化为已知特例（如均匀分布、对称情况、线性近似）时是否与已知结果一致？
4. **奇点检查**：公式在定义域内是否存在未声明的奇点或不连续点？
5. **数值插值验证**：随机取若干组参数，用公式计算与用独立方法（如蒙特卡洛、有限差分）验证，相对误差是否在合理范围内？

检查不通过时修正公式后重检，并记录修正原因。此清单补充但不替代公式必须满足的基本要求（变量先定义、量纲一致、约束明确等）。

推导跳步自检：推导过程中每个变换步骤注明所依据的规则、定理条件或代数恒等式（如"由约束资格成立故强对偶取等""两侧同加并配方"）；连续两步说不出依据即视为跳步，回补中间步骤或将该结论降级为待证表述。

### 公式与结构美学操作参考

公式除了合法，其结构与表达也影响可读性和说服力。建模定稿前可从以下操作中依次尝试与阅读对象相符者，尝试结果与取舍理由记录为候选记录或公式记录（如 `candidate_rejection_record`、`formula_validity_record`）；不适用的对象不强制尝试，数量与深度由问题结构决定：

1. **对偶化**：约束优化或线性结构是否可写对偶形式？对偶形式是否更简洁、更易解（如 KKT、Lagrange、Fenchel 对偶）？
2. **变分化**：微分方程模型是否可重写为能量泛函极小化形式，统一建模与求解？
3. **对称化**：公式或结构是否存在置换、时间反演、空间对称性可化简？
4. **压缩化**：是否存在冗余符号可消元、归一化或引入算子简写，把符号总量控制在可读范围？
5. **统一化**：多问或多次出现的结果是否可用一个生成函数、母函数或势函数参数化表达，避免重复公式？

取舍规则：若操作让公式更短、推导更直接或让读者更容易读，保留；若只是形式变换但增加理解成本，放弃并记录原因。美学不能替代验证——公式仍必须先满足合法性与绑定要求，美观只是在此基础上锦上添花。

## 图表设计契约

每张候选图在绘制前登记：

- `figure_id` 与要回答的问题；
- 必要性：没有这张图会失去什么证据；
- 源 Result、sidecar 数据和 Claim；
- 图型为何匹配变量、尺度和比较；
- 预期读者应看到的结构；
- 轴、单位、分组、样本量和不确定性；
- 颜色、排序、比例和变换；
- 误导、遮挡、过度绘制和选择性展示风险；
- 可访问性和打印尺寸；
- 若预期结构未出现，如何处理主张。

图表数量由论证需要决定。
每张图必须承载唯一证据；相同数据的多个视角只有在各自回答不同问题时保留。
不得为了看起来复杂而生成装饰图、重复图、无解释的相关矩阵或算法流程图。

常见匹配：

- 时间变化：带不确定性的折线或区间；
- 方法比较：点区间图、配对差值或有序条形；
- 分布：直方、ECDF、密度、箱线或小提琴，按样本结构选择；
- 二维关系：散点、平滑与残差；
- 矩阵：热图并标注尺度和聚类规则；
- Pareto：目标空间散点或前沿；
- 空间：等面积或正确投影地图；
- 网络：当拓扑本身是证据时使用，并配定量指标；
- 模型诊断：残差、校准、收敛、灵敏度或误差分解。

选择图型时优先可准确比较位置和长度，谨慎使用面积、体积和角度。
禁止 3D 饼图、透视柱状和会夸大差异的截断坐标。

## 图形准确性与可读性

每张图审计：

- 数据哈希和 sidecar 与绘图 execution 一致；
- 轴名称、单位、尺度和变换完整；
- 对数轴、归一化、截断和双轴明确；
- 图例术语与正文一致；
- 样本量、回测窗口或复制数可见；
- 误差棒、区间或分布与主张匹配；
- 颜色语义跨图一致且色盲可辨；
- 同指标比较使用一致轴或明确解释差异；
- 标注不遮挡数据、不越界、不被裁切；
- 图注解释对象、场景、方法、误差和主要结论；
- 在论文实际尺寸和灰度打印下仍可读。

配色服从数据语义：顺序、发散或定性。
不能仅因某色图“高级”而使用；发散色需要有真实中心，顺序值不能用周期色。

图中数值从 Result Registry 渲染，不能在绘图代码和论文各手填一次。
图注中的结论绑定 Claim；图形改变后 caption claim 自动陈旧。

自动重叠检测只能发现部分风险。
最终仍需在实际 PDF 尺寸视觉检查文字、图例、色标、线宽和留白。

### 图注结构参考

图注的写作可以按四要素组织，各要素的详略由该图承担的论证功能决定：

1. **陈述要素**：先说明图回答的对象与场景（数据、方法、条件的范围），使图注独立可读；
2. **引导观察**：指明读者应在图中看到的结构，如峰值、趋势、差异或反例的具体位置；
3. **归因与结论**：用绑定 Claim 的方式写出图支撑的结论，并明确归因于哪个模型机制或数据特征，而不是只罗列现象；
4. **限制与不确定性**：声明误差、区间、情景或适用范围的边界。

图注中的关键数值与图内标注、代码输出保持一致，三者都由同一 Result 实体渲染；图注不重复定义正文已定义的符号，也不写"从图中可以看出"式空洞引导。

### 配色建议参考

配色总体服从"顺序、发散、定性"的数据语义；以下为按图型选择配色的建议，供绘制时参考，不是固定要求：

| 图型 | 数据语义 | 建议 |
|---|---|---|
| 折线/柱状对比（多系列） | 定性 | 色盲安全定性板（如 Okabe-Ito、Paul Tol 类），本文方法用整篇唯一的强调色 |
| 热力图、相关矩阵、双因素交互 | 发散 | 有真实零中心的发散色（如 RdBu 类），中心映射在实际零值 |
| 曲面、密度、分布、等级 | 顺序 | 感知均匀顺序色（如 viridis 类），不使用彩虹高饱和映射 |
| 瀑布、误差分解 | 语义 | 正贡献与负贡献用语义色（如绿/红），并在图注说明含义 |
| 双轴图 | 成对 | 左右轴数据各一色，轴标签与数据同色，防止混淆 |
| 分类散点、网络 | 定性 | 类别数匹配的定性板，图例顺序与正文顺序一致 |

跨图一致性同样重要：同一实体（"本文方法"、某方法、某物理量）在全篇所有图中使用同一颜色与线型；同指标的多场景对比图使用一致坐标轴范围与一致色标范围，防止视觉夸张。配色建议不构成配额，图数由图承载的证据需求决定。

### 插图多样性参考

全篇图表的多样性是阅读节奏层面的可读性属性，不是数量指标；多样性以"评委逐页阅读时不因重复形态而疲劳"为准：

- **图型覆盖**：优先让不同类型的图型承担不同论证功能（折线、散点、柱状、热力、曲面、网络、分布、诊断等）；若论证确实只需少数图型，不需要为种类多而补图。
- **同类不连续**：连续多张同类图之间穿插其他图型，或把多组比较合并为子图网格，避免同类图连续堆叠。
- **样式不重复**：同一"配色+图型+布局"组合不在全篇重复出现；每张图在颜色、图型或布局至少一个维度与邻近图有所区分。
- **布局交替**：单图、双图并列、多子图网格交替使用，避免连续多张相同布局；3D 与 2D 交替而非挤在同一段落。
- **节奏穿插**：连续纯图表页用文字分析段落打破，图表密度由内容与论证需要决定。

多样性服务于可读性与论证顺序，与"每张图承载唯一证据"同属图表设计契约的一部分；不构成图型数量或比例配额。

## 三维图使用边界

3D 仅在三维语义真实且能增加信息时使用，例如真实三维空间、两个自变量与一个响应曲面、三目标 Pareto 或动力轨迹。

使用前必须证明：

- 第三维不是为装饰添加；
- 透视、遮挡和表面插值不会误导；
- 读者能读取关键值或结构；
- 需要时提供投影、切片、等高线或交互补充；
- 色彩和高度没有重复编码造成夸张；
- 静态论文视角足以支撑结论。

若二维等高线、分面或散点更准确，优先二维。
不要求固定数量的 3D 图，也不把 3D 图视为特等奖代理。

## 表格与数值

表格用于精确比较和完整列举，图用于结构识别。
表格列必须有单位、方向和定义；小数位由测量与不确定性决定，而非全表机械统一。

主结果表引用 result ID，列出场景、数据划分、样本量和不确定性。
最佳值加粗只按预登记指标和统计/实际意义规则，不因肉眼最大而标记。

派生百分比和差值由绑定系统计算。
相同字面值出现在不同指标时不可复用一个来源。

避免把所有中间输出塞入正文。
完整结果可进入允许的支撑材料，但正文必须足以判断核心结论。

### 方法对比表构造参考

方法对比表用于让评委在同一尺度下比较候选方法、基线和文献方法，其构造要点：

1. **列结构**：方法名、数据边界或场景、指标定义与方向、数值与不确定性（区间）、显著性或无差异说明、适用条件；
2. **共同基线**：所有对比方法必须与主模型共享相同的题目边界、数据边界、划分方式和评价指标，不采用各自有利的设置；
3. **比较范围**：指标从题目要求出发（精度、效率、稳健性、可解释性等），由数据和验证决定哪些可量化比较，数量由论证需要决定；
4. **结果呈现**：本文方法最优的结论只能由预登记的指标与统计/实际意义规则得出，不能因数值最大而直接标注；表现较弱的维度（耗时、内存、失败场景）应如实列入同一表；
5. **表注**：说明检验方法、显著性标注含义、基线来源与单位，使读表者无需翻正文即可理解。

对比表的位置由正文论证顺序决定；表与正文图表不重复罗列相同内容。

## LaTeX 绑定与渲染审计

稿件源使用 `MMResult`、`MMResultWithUnit`、`MMClaim`、`MMGiven`、`MMCitedValue`、`MMFormulaConstant` 和 `MMRuleValue`。
渲染前验证实体版本和完整语义，渲染后保存 binding manifest。

扫描范围包括：

- 正文和摘要；
- 表格单元格；
- 图注与脚注；
- 公式环境中的经验数值；
- 结论和建议；
- 补充说明中作为证据的数字。

公式标签、章节编号、索引和纯符号结构可按解析规则忽略。
不能整体忽略数学环境，也不能用无关 CSV 中相同数字使扫描通过。

从最终 PDF 反向抽查：随机选核心数字、图、公式和引用，追到绑定 manifest、Registry、execution 和源 artifact。
同时从 Registry 正向检查确认性 Claim 是否在论文中被准确表达，防止选择性遗漏。

编译日志中的缺字、未解析引用、溢出、浮动体和字体替换需审计。
PDF 文本抽取不是视觉渲染的完整替代；关键页面还需查看实际图像。

### 图表规划与位置核对参考

写作量大或多图多表时，动笔前可用一张规划表把每张图表映射到目标章节与引用位置（图号、论证角色、目标章节、label、宽度档位）；编译后按规划表核查：

- **位置吻合**：图表实际出现章节与规划章节相符；浮动体偏移过大时调整位置参数或整理前后段落，而不是放任漂移；
- **引用顺序**：正文首次引用顺序与图表编号顺序一致；
- **宽度统一**：同组对比图在排版宽度上一致（如并列双图同宽、单图独宽），避免同组图大小不一造成视觉误导；
- **并列一致性**：subfigure/minipage 并列时子图顺序与图注代号对应清楚。

规划表是写作工具不是门禁；写完后与 `figure_registry` 中的登记保持一致（图号、用途、源结果），防止规划、代码、论文三处各写一份的版本漂移。

## 格式匿名与占位审计

当届规则决定模板、页数、字号、页边距、语言、文件名和元数据。
不以固定页数范围代表质量。

最终扫描未完成标记：TODO、TBD、FIXME、示例文本、假数字、空表、未解析引用、重复标题和内部审查语言。
生产模板不得自带看似真实的结果、图或结论。

匿名审计覆盖正文、PDF 元数据、图片元数据、源路径、代码注释和压缩包目录。
参赛者身份字段缺失时保持本地阻塞或明确待用户填写，不由 AI 推测。

格式压缩不能牺牲可读性。
若页数超限，优先删除重复、移出非核心材料、重组图表和精炼论证；不得删掉关键限制或验证。

## 论文内容防空洞检查

空洞表述是论文质量下降的气味标记。P8 完成后和 P10 审查时对论文执行扫描，标记以下模式并要求替换为具体内容：

| 模式 | 替换要求 |
|---|---|
| 笼统评价（如"取得了较好效果"、"表现优异"） | 替换为绑定的具体数值和比较基线 |
| 模糊限定（如"在一定程度上"、"有一定的"） | 删除限定词，给出精确程度和统计依据 |
| 指向代替陈述（如"可以看出"、"显而易见"） | 直接陈述结论并绑定 Claim |
| 模板过渡（如"首先…其次…最后…"连续使用） | 使用非模板过渡，按逻辑而非序号组织 |
| 空洞前景（如"具有广阔的应用前景"） | 具体说明对什么对象、在什么条件下有什么影响 |
| 指代模糊（如"该模型"、"该方法"连续使用） | 用完整名称替代，避免指代歧义 |
| 因果连接词堆叠（如连续使用"从而"、"因此"、"进而"） | 用并列、转折或递进结构替代机械因果链 |
| 独立结论词（如"有效的"、"合理的"作为独立结论） | 必须附检验依据或证据引用 |

检查机制：

- 论文初稿完成后对以上模式逐一扫描，每发现一处标记段落并替换为绑定证据的具体内容。
- 残留空洞表述总量过高时回退修改，而非在审查中忽略。
- `quality/check_ai_patterns.py` 和 `quality/check_plagiarism_proxy.py` 提供代理扫描，但不能替代人工语义审查。

空洞表述为零是目标而非机械阈值；关键判断由内容是否被证据支撑决定。

### AI 化痕迹自查与去化写作参考

AI 化痕迹与空洞表述有关但有独立检查角度：空洞是"没有内容"，AI 化是"有内容但表达模板化"。以下痕迹可在全文（含摘要与英文版）扫描并改写：

- 高频模板开场（"随着…的发展""近年来"）→ 直接进入题目事实与决策对象；
- 机械逻辑词串（"首先…其次…最后""此外""综上所述"）→ 按逻辑关系而非序号组织；
- 无观察的评语（"结果表明本文方法有效""显著优于"无数值）→ 附绑定的数值、比较基线与条件；
- 同构段式堆叠（连续多段以"本文提出…并…"开头）→ 交替主语、从句与句式；
- 平铺单调整理（每段等长、句长均匀）→ 长短句交替，英文约 8-35 词为参考；
- 无细节的套话（"值得注意""不难发现"）→ 直接陈述结论与证据；
- 连串模板连接词（"Furthermore""Moreover"英语连用）→ 用关系与递进替换。

改写动作保留数据与论证，只改句式；不删限制词，不降证据密度。`check_ai_patterns.py` 等代理扫描只能自检，最终以外部检测与当届规则为准。

### 内容密度诊断参考

当论文某章节内容疑似单薄时，可使用以下信号辅助诊断。诊断信号不是质量门禁；内容是否充分由证据支撑和题目响应决定，不设固定页数或字数要求。

| 诊断信号 | 可能原因 | 检查方向 |
|---|---|---|
| 假设条数过少且每条缺乏必要性论证 | 问题分析不充分 | 补充每条假设的必要性、合理性、违反后果三要素 |
| 公式推导直接跳到结论，缺乏关键变换 | 推导链条断裂 | 补充决定性推导步骤和近似、误差说明 |
| 验证章节图表多但每张缺乏分析文字 | 报数不解读 | 为每张图补充数值事实层、机理解释层和决策含义层解读 |
| 讨论章节缺乏与外部文献的定量对比 | 比较不充分 | 补充与基线和已有方法的定量比较表 |
| 结论章节仅重复结果，无贡献汇总 | 总结不清晰 | 增加贡献编号列表和核心数值汇总 |

诊断后若发现实质内容缺失，回退补充推导、机理、误差、边界或决策含义；不得通过放大图片、重复图表或扩写空泛段落制造密度。

## 结果解读三层次

对每个核心结果进行三层次解读，避免"报数不解读"。三层次是写作组织方式参考，不是字数配额：

1. **数值事实层**：结果是什么。给出绑定 Registry 的数值、单位、置信区间或不确定性、场景与数据边界；确保与代码输出一致。
2. **机理解释层**：为什么是这个值。从公式结构（哪一项主导）、数据特征（分布、样本、结构）和机制（物理/经济/运筹等机理）三个角度解释数值来源，而不是复述结果。
3. **决策含义层**：这个结果对题目决策对象意味着什么。给出对实际问题的指导意义、与常识或文献的对照、可操作建议及其适用条件。

写作时先三层各一句完整表达，再按章节论证需要展开；若某层找不到实质内容，往往意味着该结果证据或理解不足，回到 P6/P7 补充验证或降低主张强度，而不是用空泛语言填充。

## 模型评价与推广参考

「模型评价与推广」回答评审必问的两个问题：这套方法做得怎么样、还能用到哪里。写作时逐维给"结论→证据→边界"，禁止无证据的形容词式自评；素材取自结果解读三层次的决策含义层与 P6/P7 已登记验证。

### 评价六维参考

每维按固定三段式组织：结论句（含量化对比或条件化表述）→ 证据句（指向 claim_id、result_id 或图表编号）→ 边界句（适用条件与已知反例）。证据不足的维度降级为"初步迹象"并写明补强路径，不硬凑。

| 维度 | 结论句骨架 | 典型证据锚点 |
|---|---|---|
| 正确性 | 在…退化/守恒条件下与解析解偏差 ≤x% | 退化场景、守恒检验 result |
| 创新性 | 相比基线，…机制使…提升 x%（附显著性） | 消融对比 result + 统计检验 |
| 实用性 | 在…数据规模下 x 分钟内给出可执行方案 | 计算耗时记录 |
| 稳健性 | 参数 ±20% 扰动下结论方向保持不变 | 灵敏度/MC 图表 |
| 可读性 | 符号 n 个全篇唯一，公式递推关系见图 | 符号表、技术路线图 |
| 计算性价比 | 精度提升 x% 的代价是耗时 y 倍 | Pareto 前沿分析 |

### 推广三路径参考

- **参数域推广**：将拟合所得机理参数替换为目标域区间后重跑验证管线；写明哪些参数须重估、哪些结构可沿用。
- **场景迁移**：列目标场景与本题在变量、约束、数据可得性上的差异清单，逐条判定 Problem Contract 哪些字段失效、哪些结论可平移。
- **方法泛化**：抽象算法骨架（输入/输出/核心假设），说明何类问题满足同构条件；可配伪代码级描述。

推广声明必须区分"已验证"与"合理外推"：外推部分标注依据来源（机理/类比）并在限制中回指；每条路径以一条 limitation 或 recommendation claim 登记，不写无条件的"可推广至各类问题"。

### 与其他章节的分工

评价章回答"本文做得如何"，讨论章（Discussion，或按需求矩阵生成的对应章节）回答"与已有工作比如何、还欠什么"——互引但不重复；结论中的贡献列表应能在六维中找到落点，未落点的贡献回炉补证或删除。章节编号以本稿需求矩阵生成的结构为准，不预设固定编号。

## 多问题目衔接规范

多问题目的论文是一个整体，不是独立小论文的拼接。每个小问开头应包含显式的逻辑衔接：

1. **承上**：总括前一问的核心结论，引用其 Result 和 Claim 实体而非模糊指代。
2. **启下**：说明本问与前问的逻辑关系——数据依赖、模型扩展、约束传递或方法迁移。
3. **本问定位**：一句话点明本问的数学本质和解决思路。

衔接引用必须绑定实体。例如"Q2 使用 Q1 的参数估计"必须引用参数 Result 和不确定性，而不是只写"根据上文结果"。

若不同小问使用不同模型，论文必须解释接口和依赖，不强行包装成不存在的统一模型。问题分析章可以包含耦合关系有向图——节点为各问，有向边为数据、模型、结果或理论传递关系，图注说明每条边的含义并绑定源实体。

## 核心主张贯穿

论文应有一句贯穿全文的核心发现或洞见作为主题锚定。这句话在摘要中首次出现，在方法章节被论证，在验证章节被检验，在结论中回顾。

金句不是口号或形容词堆叠，而是可绑定的核心主张：

- 包含具体的数学结构或决策洞察；
- 绑定到 Claim Registry 中的确认性主张；
- 在全文各章节被证据反复支撑而非重复空喊；
- 诚实反映模型能做什么和不能做什么。

若论文的核心价值是严谨验证而非方法创新，金句可以表述为"在 X 条件下，本文证明 Y 的适用边界为 Z"，不强求"首次提出"或"全面超越"。

## 创新点展示格式

创新点索引表帮助评委快速定位每个创新的来源和证据。论文中可包含一张映射表：

| 列 | 内容 |
|---|---|
| 问题 | 对应的 Requirement ID |
| 方法 | 具体方法名称和关键结构 |
| 创新类型 | 新结构、非平凡推导、识别突破、决策洞察或可迁移方案 |
| 证据 | 绑定的 Execution、Result 和 Validation 实体 |
| 基线对比 | 与最低合理基线的定量差异 |
| 适用边界 | 失效条件和限制 |

创新点数量由真实贡献决定。若主要价值是验证或边界界定，诚实表述即可，不把常规算法改名为原创。

### 创新点三段式配方（从发现到论文的贯通路径）

每个进入索引表的创新点按同一管线完成"发现→证据→表述"闭环，杜绝泛化表述：

1. **发现段**：创新来源必须可定位到三类实体之一——反直觉/矛盾发现
   （`counterintuitive_finding_record`）、跨问统一框架
   （`cross_problem_framework_record`）、方法结构性改进（候选淘汰记录中
   的胜出差异）。找不到来源实体的"创新"不进索引表。
2. **证据段**：每条创新绑定一个最小证据组合——消融
   （`innovation_ablation_record`）+ 定量基线差异 + 一条边界/反证检验；
   定理型创新用 `theorem_application_record` + 边界特例数值检查替代消融。
3. **表述段**：摘要与结论中的创新句采用"机制→效果→边界"三要素模板：
   "通过〈具体机制〉，在〈条件〉下将〈指标〉提升/界定至〈量化值〉，
   其适用边界为〈限制〉"；三要素缺一时降级为严谨实现表述。

该配方与 P4-P6 的深度证据类型一一对应：启用 deep-insight profile 时，
索引表每行都应能在 Registry 中找到其发现段与证据段实体。

## 方法谱系定位图

当论文使用多个方法或与多种已有方法比较时，可包含一张方法谱系图展示"本文方法"与已有方法的分类关系。该图帮助评委快速理解学术定位：

- 树形或分类图，节点为方法族，标注关键差异维度；
- "本文方法"在图中明确标注位置和与父类方法的关系；
- 图注解释分类依据和本文方法的结构性差异；
- 不替代正式的基线比较表，只提供导航视角。

此图仅在方法间存在真实结构性差异时绘制；若所有候选属于同一方法族的不同参数配置，不需要谱系图。

## 长公式排版规范

长公式的 LaTeX 排版影响论文专业感和可读性：

- 多行公式使用 `align` 或 `split` 环境，对齐点放在关系符（=、≤、≈）处。
- 超宽公式优先拆分为逻辑步骤，每步附简短文字说明变换目的，而非机械展开全部代数。
- 编号公式必须有 `\label`，且在正文中被 `\ref` 或 `\eqref` 引用。
- 未编号公式放在 `align*` 或 `equation*` 中，确保不产生空编号。
- 公式中的变量在首次出现处定义；后续章节使用同一符号时引用首次定义位置。
- 经验常数使用 `\MMFormulaConstant` 绑定到来源证据。
- 行内公式不宜过长；超出三分之一行宽的公式应独占一行。

公式排版错误（未对齐、溢出、空编号、交叉引用断裂）属于渲染审计范围，P8 门禁检查时与文本绑定一起扫描。

## 算法伪代码排版规范

关键算法用伪代码呈现可显著提升可读性与专业感：

- 使用 `algorithm2e`（如 `\usepackage[ruled,linesnumbered]{algorithm2e}`）或 `algorithm` + `algpseudocode` 组合；全文只选一套风格，不混用。
- 每个伪代码环境显式声明 `Input`/`Output`，开启行号，关键步骤附简短注释说明目的而非复述语句。
- 主循环或复杂分支标注收敛、停止条件与计算复杂度（时间/空间，含输入规模记号），并与理论分析小节相互呼应。
- 伪代码环境必须有 `\label{alg:...}` 且在正文中被 `\ref` 引用至少一次；未被引用的伪代码按孤儿处理，随渲染审计清零。
- 伪代码与 production execution 绑定的实现保持语义一致：变量名与符号表一致、步骤顺序一致、默认参数一致；论文数值不得来自未出现在伪代码或代码中的步骤。
- 直接调用标准库或单步求解的简单算法不必强行伪代码化；以读者能否更快理解实现为准。

## 阶段验收

P8 和 P10 论文门禁必须证明：

- 所有赛题要求映射到论文位置和 Claim；
- 摘要核心数字、结论和贡献有绑定证据及范围；
- 符号、单位、假设、公式和小问依赖一致；
- 每张图有必要性、sidecar、源结果、主张和误导风险审计；
- 图表数量由论证需要决定，没有固定配额或装饰性 3D；
- 表格和图中的值与 Registry 当前版本一致；
- 裸科学数字、未解析引用和占位内容为零；
- LaTeX 源、binding manifest、渲染稿和最终 PDF 互相一致；
- 实际尺寸视觉检查、匿名和当届格式检查完成；
- 空洞表述已被替换为绑定证据的具体内容；
- 多问题目衔接引用了前置 Result 和 Claim；
- 长公式排版无溢出、空编号或交叉引用断裂。

页面数量、图像文件大小、关键词和模板章节存在不能自证论文质量。


## 附录：v2 出版闭包

### publication execution 闭包

- P8 的 `manuscript_source` 证据必须声明 `publication_execution_id`：受控编译 execution。
- binding manifest 必须是 v2；v1 manifest 只用于只读兼容审计，不能用于 v2 最终发布。
- 根稿件、每个递归包含文件与 manifest 一起构成闭包：rendered 稿件与 manifest 必须是该 publication execution 的 production 输出；递归包含源必须要么是该 execution 的 production 输出，要么是登记过的不可变 external 依赖（哈希可验证）。
- 每个闭包源都有 artifact 绑定（path + sha256 一致），渲染后替换 included 源、漏登 .bib/样式、使用另一 execution 的 PDF 都会使 P8 失败。

### 绑定宏

- `\MMResult{result_id}`、`\MMResultWithUnit{result_id}` 单参数，以 Registry locator 为权威；`\MMClaim{claim_id}{text}` 必须与 Claim Registry 文本一致且强度合格；`\MMRuleValue{requirement_id}{field}` 解析官方规则要求字段。
- 渲染产物中残留任何绑定宏即失败；未绑定科学数字扫描基于绑定掩码与上下文分类。
