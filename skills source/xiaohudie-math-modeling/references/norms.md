# 数模竞赛总纲：节奏、评委视角与扣分点

> xiaohudie 独立整理的竞赛总纲（社区实践参考出处见 SOURCES.md）。本文管全局节奏与质量底线，细节在其余参考文档。

## 评委视角的四条评阅原则

1. **假设的合理性**：假设必须服务于建模，不能是凑数的废话；每条假设要在正文建模处被引用，否则形同虚设。
2. **建模的创造性**：多模型对比、创新方法、非标准解法加分；创新体现在"问题适配度"而非算法堆砌——先用简单基线（线性回归/简单机理模型）建立可解释基准，性能不足再升级并解释改进点。
3. **结果的正确性与合理性**：数值物理合理、约束不违反、限制情形下行为符合预期；启发式不宣称全局最优。
4. **表述的清晰性**：逻辑连贯、可视化专业、读者能复现。

## 常见扣分点速查（写作侧）

- 假设没在正文引用 → 形同虚设。
- 结论只给数值不解释含义。
- 图表无引导无解释、连续堆图。
- 公式符号首次出现未定义。
- 摘要与正文数值不一致（摘要最后写、从正文复制数值可避免）。
- 参考文献捏造或无法核实 → 严重信誉问题。
- 正式痕迹泄漏：正文出现内部文件名/工作流说明/"由 AI 生成"。

## 常见扣分点速查（建模与代码侧）

- 优化漏非负/整数/容量/预算/时间窗/前驱约束；连续松弛后取整不验证可行性。
- 优化变量无物理边界（桌面模型给出数米构件）。
- 多目标不做无量纲化直接加权相加。
- 时序用未来信息训练（数据泄露）；标准化在全集 fit。
- 评价类不说明指标正负向、权重来源，不做敏感性检验。
- 微分方程不写初始/边界条件、不查守恒量、不做步长收敛性检查。
- 图论不检查负权边/连通性/子回路。
- 机理题套数据分析模板（画直方图、提异常值清洗）。
- 蒙特卡洛次数太少、不报置信区间。

## 时间管理（三天赛制参考）

| 阶段 | 时间 | 要点 |
|---|---|---|
| 选题 | 第1天上午 | 全队读 3 道题各 30 分钟，列每题的模型方向与数据可得性，选把握最大的；**定了不换题** |
| 分析与建模 | 第1天下午-晚上 | 拆解子问题、查文献、定模型；先出问题1的完整方案 |
| 编码求解 | 第1天晚-第2天 | 边做边写：每问求解完成立即写该问论文章节，不要等全部算完 |
| 论文与摘要 | 第2天-第3天上午 | 检验、灵敏度、摘要（最后 6 小时留给摘要打磨与全文校对） |
| 提交 | 截止前 1 小时缓冲 | PDF/MD5 按赛事要求；留出上传失败重试时间 |

## 团队分工建议

- 建模手：负责模型选型与数学表达，同时是论文主笔之一。
- 编程手：负责求解代码与可视化，产出结果记录。
- 写作手：负责论文组织、摘要打磨、格式与引用规范。
- 三人都要参与选题讨论；写作手从第 1 天就动笔，不要等结果齐了再写。

## 摘要五要素（评委只认真读摘要）

每个子问题的摘要段必须覆盖：① 问题类型判断；② 用了什么模型/方法；③ 怎么构建与求解；④ **具体数值结果**；⑤ 效果评价。最后一段总结灵敏度分析与整体结论。

## 论文验收清单（交付前逐项过）

- [ ] 摘要：一页内、每问有数值、与正文一致、关键词 4-6 个
- [ ] 问题重述：不照抄题面，是建模者的重新表达
- [ ] 假设：每条必要、可解释、在正文被引用
- [ ] 符号：全后文符号已定义、含量纲
- [ ] 模型章：三要素完整（优化类）、公式有编号步骤与变量说明、参数有来源
- [ ] 检验：误差分析 + 灵敏度分析都有
- [ ] 评价：优点多于缺点，有具体依据
- [ ] 参考文献：真实、8-15 条、每条被引用
- [ ] 图表：全部被引用、无 set_title、语言一致、矢量清晰
- [ ] 编译：0 Error、无 Overfull、无占位符、摘要 1 页
- [ ] 合规：AI 使用声明按赛事要求（见 compliance.md）
